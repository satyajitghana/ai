LFM3 verification run, 2026-10-31. CPU only, 2 threads (OMP_NUM_THREADS=2, torch.set_num_threads(2)), shared 4-vCPU box.
torch 2.14.1+cu130 (CPU use), transformers 5.20.2, python venv /root/kokoro-venv.
Model: LiquidAI/LFM3-1.7B (model.safetensors, bf16), modelling code downloaded with the weights and loaded via
  AutoModelForCausalLM.from_pretrained(dir, trust_remote_code=True, dtype=torch.bfloat16). Code skimmed first: imports only
  torch/transformers, Triton kernels used only if CUDA; no network/subprocess/pickle.
Comparison model: Qwen/Qwen3-1.7B (28 full-attention layers, 16 q heads, 8 kv heads x 128), bf16, same script, native transformers class.

Commands (order run):
 1. hf_ref.py CODE_DIR OUT --logits          -> real full-position logits for 4 chat prompts (18-23 tokens) + greedy text (hf_greedy.json)
 2. ours_vs_hf.py CODE_DIR OUT_logits.npz logit_agreement.json
      our lfm3_ref.py block structure, bf16 weights, bf16 matmuls (no int8), fp32 elementwise/attention, one token at a time
 3. hf_ref.py CODE_DIR OUT --long --decode 256,1024,4096,8192 -> 320-token logits (crosses the 256 window) + decode timing
    ours_vs_hf.py ... logit_agreement_long320.json
 4. hf_ref.py CODE_DIR OUT --decode 16384,32768   (LFM3, lfm3_decode_16k_32k.json)
 5. hf_ref.py QWEN_DIR OUT --decode 256,1024,4096,8192,16384   (qwen3_1.7b_decode_256_16k.json, qwen3_run.log)
Decode timing: context filled by chunked prefill (512 tokens a chunk) of a repeated English sentence, then 7 single-token
decode steps with the KV cache; median of steps 2-7 reported (first step dropped). Load was shared with other agents; noise ~10-20%
(LFM3 1K median 383 ms is a noisy outlier; its min is 283).
Weights deleted after the runs (disk).
